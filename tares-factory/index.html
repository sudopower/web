What Tares does about it

  1. 01

    Re-briefed after compaction

    After any compaction or resume, a SessionStart hook tells the station who it is. It reloads its skills, re-reads its report and its work on Tares, and re-arms its schedule.

  2. 02

    State outside the context

    A report file and Tares hold the state. Compaction loses nothing that matters.

  3. 03

    Room to work

    200k tokens by default, at least 150k. At 100k a station refilled right after every compaction.

  4. 04

    Thrash guard

    The watch spots Claude Code's “autocompact is thrashing” stop and starts the station fresh under the same name.

  5. 05

    In plain sight

    The Crew page shows how near each station is to compacting, and its context by category on request.

Still open

No early warning at 50% or 70% yet. Nothing hands work over before compaction happens.

What's
unique

Compared with Claude Code and coding agents in general.

  1. 01

    One owner per action

    A guard hook enforces it, and runs heavy commands one at a time.

  2. 02

    A second model reviews

    Optional: Codex reviews every commit and blocks on serious findings until fixed.

  3. 03

    Tests must fail on broken code

    The reviewer proves each new test fails against broken code.

  4. 04

    Not only for code

    The same store serves timelines and triggers for other agents, such as an AI SRE.

  5. 05

    Any MCP agent WIP

    Works with any MCP agent, not only Claude Code.
